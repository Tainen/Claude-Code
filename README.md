# 株式会社VOCO給与管理システム

社員一人ひとりがアカウントを持ち、基本給・RPO案件・採用イベント受注を登録すると、
給与とインセンティブが自動計算される SaaS 型の給与算出システムです。
他のメンバーの給与は本人からは見えません（オーナーのみ全員分を閲覧できます）。

## 起動方法

```bash
npm install
npm start          # http://localhost:3000
```

- データは `data/voco.sqlite` に保存されます（`DB_PATH` 環境変数で変更可能）。
- ポートは `PORT` 環境変数で変更できます。
- **最初に登録したアカウントがオーナー（管理者）になります。** 2人目以降はメンバーです。

## テスト

```bash
npm test
```

## 社員への展開（インターネット公開）

このリポジトリには [Render](https://render.com) 用の `render.yaml` と、
Docker が使えるサービス（Railway など）用の `Dockerfile` が含まれています。

### Render での公開手順（推奨）

1. https://render.com にサインアップし、GitHub アカウントを連携する
2. ダッシュボードで「New +」→「**Blueprint**」→ このリポジトリを選択
3. `render.yaml` が自動で読み込まれるので、そのまま「Apply」
4. 数分で `https://voco-salary-xxxx.onrender.com` のような URL が発行される

※ 給与データ（SQLite）を消さないための永続ディスクには有料プラン
（Starter、月 $7 程度 + ディスク代）が必要です。無料プランはデプロイや再起動のたびに
**データが消える**ため、本番運用には使わないでください。

### セキュリティ

- **招待コード**: 最初のオーナー登録時に自動生成されます。2人目以降の登録には
  このコードが必要なので、URL を知られても社外の人はアカウントを作れません。
  コードは「設定」タブ（オーナーのみ）で確認・変更できます。
- HTTPS 経由ではセッション Cookie に `Secure` フラグが付きます。
- 公開後、最初に必ずオーナーアカウントを登録してください（1人目がオーナーになります）。

## 給与計算ルール

### 支給サイクル

売上（イベント開催・RPO月次粗利）が発生した月の翌月にお客様から入金があり、
インセンティブは入金月より後の直近のクォーター月（**1月・4月・7月・10月**）に支給されます。

| 売上発生月 | 入金月 | インセンティブ支給月 |
|---|---|---|
| 12月・1月・2月 | 1〜3月 | 4月 |
| 3月・4月・5月 | 4〜6月 | 7月 |
| 6月・7月・8月 | 7〜9月 | 10月 |
| 9月・10月・11月 | 10〜12月 | 翌1月 |

### 基本給

最初に登録した基本給が毎月そのまま適用されます。金額が変わる場合は
新しい発効年月で追加登録すると、その月以降は新しい額が適用されます。

### 採用イベントのインセンティブ

同じ**受注月**の合計枠数に応じた段階単価です。

| 受注月内の通算枠数 | 1枠あたり |
|---|---|
| 1〜5枠目 | 20,000円 |
| 6〜10枠目 | 40,000円 |
| 11枠目以降 | 60,000円 |

例: 1ヶ月で11枠受注 → 5枠×2万 + 5枠×4万 + 1枠×6万 = **36万円**

単価の割り当ては登録順ではなく**イベント開催日が早い順**です。
例えば同じ月に「10月開催×3枠」→「4月開催×3枠」の順で受注しても、
4月開催の3枠が1〜3枠目（各2万円）、10月開催が4〜6枠目（2万・2万・4万円）になります。
各枠の支給月は、その枠のイベント開催月から上の表で決まります。

### RPO のインセンティブ

RPO案件（半年または1年契約）は**オーナーが登録**し、社員は案件一覧から
**メイン担当またはサブ担当**を自分で選びます。1人が複数社を担当でき、
同じ担当（メイン/サブ）に複数人がつく案件もあります。

**複数人で同じ担当につく場合、案件の粗利は人数で等分**して計算されます
（例: 粗利80万円でメイン2人 → 各40万円分として扱う）。

**保有額**は「按分後粗利 × 担当割合（メイン80% / サブ20%、オーナー設定）」で換算します。
例: メインで月100万円の案件を2つ → 160万円の保有（150万円超〜200万円帯）。
メイン100万×2 + サブ100万×2 → 80+80+20+20 = 200万円の保有。

支給月の対象3ヶ月それぞれについて、
「その月の保有額合計 × 保有額帯（50万円刻み）ごとの率」が支給されます。

| 保有額帯（50万円刻み） | 率（オーナー設定・初期値） |
|---|---|
| 〜50万円 | 3% |
| 50万円超〜100万円 | 3% |
| 100万円超〜150万円 | 5% |
| 150万円超〜200万円 | 7% |
| 200万円超〜250万円 | 10% |
| 250万円超〜300万円 | 10% |
| 300万円超 | 10% |

| 担当 | 割合（オーナー設定・初期値） |
|---|---|
| メイン担当 | 80% |
| サブ担当 | 20% |

### 損益グラフ（粗利の可視化）

- 月次粗利 = **RPO保有額（メイン80% / サブ20%換算）＋ イベント受注合計（枠数 × 枠単価）の50%**（**受注した月**に計上。開催日・振込日は無関係）
- イベント受注時に「枠単価（1枠あたりの受注金額）」を登録すると粗利に反映されます（例: 2枠 × 20万円 = 受注合計40万円）
- 同じイベントで枠ごとに金額が異なる場合は、単価ごとに分けて登録できます
- 基本給が「粗利 × 損益ライン%（初期値30%・オーナー設定可）」以内なら**黒字（青）**、
  超えると**赤字（赤）**の棒グラフで表示（黒字は**青**）
- メンバーは自分の損益、オーナーは**全社合計**（全員の粗利・基本給を合算して損益判定）と全メンバーの損益を閲覧できます

### イベントの編集

オーナーは登録済みイベントの名前・開催日を後から編集できます。
開催日を変更すると、支給月や枠単価の計算にも自動で反映されます。

## 構成

```
src/calc.js    給与・インセンティブ計算ロジック（純粋関数）
src/db.js      SQLite スキーマ・設定値
src/auth.js    セッション認証（scrypt によるパスワードハッシュ）
src/server.js  Express API サーバー
public/        フロントエンド（SPA）
test/          計算ロジックのテスト
```

依存は Express のみで、DB は Node.js 組み込みの `node:sqlite` を使用しています（Node.js 22 以降が必要）。
