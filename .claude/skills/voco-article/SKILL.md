# VOCO お役立ち記事 作成スキル

## 目的
voco.co.jp（Studio製）の「お役立ち記事」に載せる記事を、毎回同じ品質・同じ型で1本仕上げる。
最終確認と Studio への掲載は人（堀本さん）が行う。ここでの成果物は「そのまま貼れる状態の原稿」と「カバー画像」。

## 成果物（1記事あたり）
1. Google ドキュメント：`No.{番号}_{タイトル}`（Drive「HP / お役立ち記事」フォルダ、ID `1klA79rJRmpGTfMJZUL5fUFr2ViNZ0Bfj`）
   - 先頭に「掲載用メタ情報」（タイトル・メタディスクリプション・カテゴリ・想定文字数・参考にした資料URL）
   - 本文は Studio のリッチテキストに貼れる構造のみ使う：H2 / H3 / 段落 / 箇条書き / 番号付き / 引用 / リンク。表・画像埋め込み・インラインCSSは使わない（Studio側で崩れる）
2. カバー画像 PNG：`No.{番号}_cover.png`（同フォルダ、1200×630）
3. HubSpot にブログが存在する場合のみ：同内容を **下書き** で作成（公開はしない）
4. 作業ログ：作った物のURL、参考にした資料、迷った点を最後に短く報告する

## 手順

### 0. 準備
- リポジトリのブランチ `claude/voco-homepage-articles-ys5zwk` を取得し、`content/articles/themes.md` と本ファイルを読む。
  `git fetch origin claude/voco-homepage-articles-ys5zwk && git checkout claude/voco-homepage-articles-ys5zwk`
- Drive フォルダ `1klA79rJRmpGTfMJZUL5fUFr2ViNZ0Bfj` を `parentId` 検索で一覧し、既に存在する `No.xxx_` のファイル名を控える。

### 1. テーマ選定
- `themes.md` の表を上から見て、Drive に `No.{番号}_` で始まるドキュメントが **無い** 最初の行を採用する。
- 全て消化済みなら、消化済みテーマと重複しない新テーマを1つ自分で決め、報告に「themes.md への追記案」として書く。

### 2. リサーチ（競合のお役立ち資料・記事を「構成の参考」にする）
- WebSearch を 3〜5 回。検索語は「狙う検索語」＋「参考にする競合テーマ」＋「新卒」「中小企業」など。
- 参考にするのは新卒採用コンサル・採用代行（RPO）を実際に提供している会社の記事・お役立ち資料。例：ネオキャリア「みんなの採用部」、マルゴト「まるごと人事」、ワンキャリア（採用担当者向け）、HRプロ、アールナイン、i-plug、キャリタス、マイナビ／リクルートの調査レポート。
- 見るのは「見出し構成」「読者が求めている論点」「よくある結論」「使われている統計の出典」。**本文の文章は写さない。** 独自の数値を使うときは出典（社名・調査名・年）を本文中に明記する。出典が確認できない数値は使わない。
- この環境では多くの外部サイトを直接開けない（プロキシで拒否される）。開けない場合は検索結果の要約の範囲で構成を把握し、無理に本文取得を試みない。

### 3. 執筆
- 分量 2,000〜3,000字。H2 を 3〜5 本。1 見出し 300〜600 字。冒頭 2 段落で「読者の悩み」→「結論」を先に出す。
- 構成の型：①悩みを言い当てる → ②結論 → ③現場で見た具体例 → ④今日からできる手順 → ⑤まとめ（箇条書き）→ ⑥CTA
- 読者：採用担当がいない、または片手間で採用している中小企業の経営者・総務・人事。主に関西・東海。
- 文体：です・ます。断定は「現場で見た範囲」に限る。盛らない、誇張しない、読者を責めない。VOCO の宣伝は本文の 1 割以下。
- VOCO の立場：採用担当として企業の現場に入って実働する会社。年間200回以上イベント登壇。部活動の公式活動として開催する採用イベントを主催。「知見ごと渡し、自走できる組織にする」が思想。
- タイトル：32字以内、検索語を前半に。「〜とは」「〜の方法」「〜チェックリスト」「〜3つの◯◯」のいずれかの型。
- メタディスクリプション：100〜120字。結論と誰向けかを含める。
- CTA（固定文言。変えない）：
  「採用のことを、一度話してみませんか。」
  「どんな段階でも構いません。「まだ検討中」でも大歓迎です。採用のプロが、貴社の状況に合わせてお答えします。」
  ［今すぐ無料でプロに相談する］［資料3点セットをダウンロードする］

### 4. 使ってよい VOCO の数字・事例（HPテキスト確定版 2026年4月 に準拠。これ以外の社内数字は使わない）
- 年間200回以上のイベント登壇／30都道府県・20業種の支援実績／クライアント総合計40名採用／契約更新率92%
- 採用フルサポート：採用業務の90%以上を担当／契約後に3日〜1週間の業務体験インターン／メイン1名＋サブ1名の固定2名体制／最短半年契約／週1回以上の定例MTG、365日相談対応
- 採用イベント：部活動の公式活動として開催／学生3〜5名のグループ面談形式／3年生中心に20名以上動員／15万〜40万円/回（税抜）・追加料金なし／一般的な大規模イベントは50万〜90万円／開催エリアは北海道・関東・東海・関西中心
- 採用資料作成：ヒアリングから納品まで通常3〜4週間
- 公開事例（この文面の範囲で触れてよい）：鈴木自工（説明会→面接の歩留まり改善）／MIRAIHOME（採用実務の外注で社内負担軽減・コスト効率向上）／第一カッター興業（自社主導へ、ナビ・人材紹介依存から脱却）／菊谷茂吉商店（初の新卒採用を立ち上げから入社まで一貫支援）
- **使わない**：商談で聞いた個別企業の数字、社内向け資料の表現、未確定セクション「VOCOと組む前に」、他社の固有名詞を悪く言う表現

### 5. カバー画像
- 標準：`node tools/article/make-cover.mjs --title "<タイトル>" --category "<カテゴリ名>" --out <出力パス> [--variant dark|light]`（ブランド準拠のタイトルカード。奇数番号は dark、偶数番号は light）
- 環境変数 `GEMINI_API_KEY` がある場合のみ AI 画像生成を追加で試す（`tools/article/make-image-gemini.mjs`）。失敗したらタイトルカードにフォールバックし、報告に書く。
- 画像内に人物の顔・他社ロゴ・実在の学生写真風の表現は入れない。

### 6. 出力
- Google Drive：`create_file` で Doc（`contentMimeType: text/html`、`parentId` は上記フォルダ）と PNG（`base64Content`、`contentMimeType: image/png`、`disableConversionToGoogleType: true`）を作成。
- HubSpot：`manage_blog_post` の `LIST_BLOGS` でブログが 1 つ以上あれば、`CREATE` で下書きを作る（`metaDescription` とタグを付ける。タグは `LIST_TAGS` にある既存のものだけ。無ければタグなし）。**PUBLISH は絶対にしない。** ブログが無ければ HubSpot は触らない。
- 途中で失敗しても、できた成果物の URL は必ず報告する。

### 7. 公開前チェック（報告の末尾に○×で付ける）
- [ ] タイトル32字以内・検索語が前半にある
- [ ] 2,000〜3,000字、H2が3〜5本
- [ ] 数字はすべて「第4項の一覧」か「出典明記の外部統計」のどちらか
- [ ] 他社記事の文章の写しがない
- [ ] 盛った表現・断定しすぎ・読者を責める表現がない
- [ ] CTA が固定文言のまま
- [ ] Doc と PNG が Drive フォルダにある

## 7分類（カテゴリ）
1 新卒採用の基本・進め方／2 採用イベント・合同説明会／3 母集団形成・学生との接点／4 会社説明会・採用資料・伝え方／5 内定者フォロー・辞退防止／6 採用体制・採用代行の選び方／7 地方・中小企業の採用

## Studio へ貼るときの手順（堀本さん向けメモ）
1. Studio ダッシュボード → CMS → 「お役立ち記事」モデル → アイテム追加
2. タイトル・スラッグ（`article-{番号}`）・カテゴリ・公開日を入力
3. Doc の本文を H2/H3/段落ごとにリッチテキストへ貼る（Doc からコピーすると見出しレベルも保持されることが多い）
4. カバー画像 PNG をサムネイル／OGP に設定
5. 保存 → 公開。TOP の「お役立ち記事」枠は週1で最新3本に差し替え
