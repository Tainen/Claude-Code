# VOCO ニュース記事 作成スキル

## 目的と役割分担

- voco.co.jp の「ニュース」に載せるお知らせ原稿を、毎回同じ型・同じ品質で1本仕上げる。
- 人（堀本さん）がやること：事実の提供、写真の用意、締結式の日時などの確定、Studio への入稿・公開。
- このスキルがやること：リサーチ、執筆、機械チェック、Google ドキュメント化、Drive への出力、報告。
- 参照：`content/news/README.md`、`tools/article/check-article.mjs`、`tools/article/make-doc-html.mjs`。

## 成果物（1記事あたり）

1. `content/news/news-00X_{英数スラッグ}.html` … 正本。先頭の HTML コメントにメタ情報・埋める箇所・確認事項・出典を書く。本文は `<h2> <h3> <p> <ul><li> <a>` のみ。
2. Google ドキュメント `news-00X_{タイトル}` … Drive「01_HP / ニュース」フォルダ（ID `1hAAAyqf4tiFePA6kGjUMI2xxIpVlJKJR`）。
3. 報告：Doc の URL、Git のパス、調べて分かったこと、埋める箇所、確認してほしい点。

## 手順

### 0. 準備

- `git pull` で最新化し、`content/news/` の既存記事を1本読んで型を確認する。最新の型は `news-003`（法政）・`news-005`（中京）・`news-006`（鈴鹿）。
- 次の番号を決める（`ls content/news/`）。

### 1. リサーチ

**外部サイトは WebFetch より curl が通ることが多い。** WebFetch が `ENOTFOUND` を返しても、`curl -sS --max-time 25 <URL>` なら取得できる場合がある。両方試す。

調べる順番：

1. **部の公式サイト**（創部年、部員数、監督・主将、理念・スローガン、拠点）
2. **大学の部活動紹介ページ**（公式サイトに無い情報が載っていることが多い）
3. **連盟の公式サイト・大学のスポーツ情報サイト**（戦績。例：`chukyo-sports.com/game` のように試合結果ページを持つ大学がある）
4. **報道**（ゲキサカ、伊勢新聞、地方紙など。順位・試合結果の裏取り）
5. **既存スポンサーの有無**（後述。必ず調べる）

JS で描画されるページは、生HTMLに本文が無くても `<script>` 内の JSON に入っていることがある。`grep` でキーワードを探してから判断する。

### 2. 必ず調べる3つの落とし穴

**① 呼称（最重要）**
その部に**すでにメインスポンサーがいないか**を必ず調べる。「〇〇大学〇〇部 スポンサー」「メインスポンサー 就任」で検索する。

- 法政：ニュー・クイックがメインスポンサー就任済み（ユニフォーム胸上部）→ 当社は「オフィシャルスポンサー」
- 南山：複数社と契約済み、部の呼称は「協賛パートナー契約」→「スポンサー契約」「協賛パートナー」

**メインスポンサーが埋まっているのに「メインスポンサー」と書くと事故になる。** 調べた結果を先頭コメントに必ず書き、堀本さんに判断を仰ぐ。

**② 監督・主将の年度差**
公式サイトのスタッフページが更新されていないことが多い。最新の試合報道と食い違う場合は、報道側を採用し、食い違いを先頭コメントに明記する（例：法政の監督は公式サイトが糸久正人氏のまま、報道は柳沢将之監督）。

**③ 人名・団体名を出すリスク**
プロ選手名、他社名を本文に出すと、読み手に「その人・その会社が関わっている」という誤解を与えうる。肖像・パブリシティ権の観点でも、**名前を出さない差し替え文を用意したうえで、公開前の判断を仰ぐ**（鈴鹿の田宮選手の例）。

### 3. 構成（8見出し。これを変えない）

1. リード2段落（概要＋当社の立ち位置）
2. 【画像：締結式の集合写真】
3. `<h2>` スポンサー契約の概要（箇条書き：対象／支援開始／締結式／支援内容）
4. `<h2>` 〇〇との締結理由
5. `<h2>` 〇〇 代表コメント（`●●` で空ける）
6. 【画像：部の活動風景】
7. `<h2>` 〇〇について
8. `<h2>` 2026年の戦績
9. 【画像：VOCOのロゴ入り／支援物品】
10. `<h2>` 支援の内容
11. `<h2>` 株式会社VOCOについて
12. `<h2>` 関連リンク
13. CTA段落

自社の取り組み（米づくりなど）は別構成でよい。その場合は一人称の感想を軸にし、末尾に署名行を置く（`news-004` 参照）。

### 4. 文体（指摘を受けて確定したルール）

- **です・ます調で統一する。** 言い切りの文（「学生はたくさん集まった。」）を途中に混ぜない。臨場感を出そうとして文体を変えると「構成が変わりすぎ」になる。
- **短く切って余韻を作る書き方をしない。** 「〜こと。それが〜」「〜である。」のような構えた形は使わない。ポエムっぽいと指摘される。
- **抽象語を使わず、事実と数字で書く。** 「気持ちの入り方」「積み重ね」「〜と感じます」ではなく、「練習と試合に充てている時間の量」「毎年Jリーグへ進む選手が出ている」と書く。
- **一文だけの段落で主旨を引っ張らない。** 「一番の理由は、○○です。」で区切って次段落で説明する形は、溜めを作る構成そのものが詩的に見える。通常の段落に統合する。
- **体言止めを使わない。** 「部員は70人弱。」→「部員は70人弱で、」
- **上から目線にしない。** 「支援先に求めるのは2つです」のような選定基準の提示はしない。「ご一緒したいと思ったのは、次の点に惹かれたからです」と書く。学生の挑戦は「私たちへの問いかけ」として受け取る形にする（サステナビリティページの考え方）。
- スローガン（「挑む者に、挑み続ける背中を。」）を本文の一文目に置かない。タグライン自体が詩的で、全体が引っ張られる。

### 5. 数字と事実の扱い

- **確認できない数字は書かない。** 推測で埋めない。
- 出典が食い違う場合は、**本文には書かず**、食い違いを先頭コメントに記録する（部員数が60人/64名で割れている、など）。
- 戦績は**都合のいい部分だけ切り取らない**。春優勝・秋3位なら両方書く。削るかは堀本さんの判断に委ねる。
- 確定していない事項（締結式の日時、支援開始、支援の用途、代表コメント）は `●●` で空け、先頭コメントの「埋める箇所」に番号付きで列挙する。

### 7. 機械チェック

```
node tools/article/check-article.mjs content/news/news-00X_xxx.html --target 2200 --tolerance 0.15
```

H1 なし／段落150字以内／全角スペース・Markdown記法・擬似ボタンなし を確認する。
**「H2 が 8 本」「まとめの H2 がない」の NG はお役立ち記事用の基準なので、ニュースでは無視してよい。**

### 8. Google ドキュメント化と出力

```
node tools/article/make-doc-html.mjs --file content/news/news-00X_xxx.html --no-img --out /tmp/.../doc.html
```

- `--no-img` は必須。ニュースの写真は部や取引先から受け取るため Git に画像が無く、`<img>` にすると壊れる。「［ここに画像Nを入れる］」のプレースホルダーになる。
- 生成した HTML を `mcp__Google_Drive__create_file`（`contentMimeType: text/html`、`parentId` は上記フォルダ）でアップロードする。ファイル名は `news-00X_{タイトル}`。
- Git（`content/news/`）に正本をコミットし、ブランチに push する。

**既に Doc がある記事を直すときは、新規作成せず `mcp__Google_Docs__update_doc` の `replaceAllText` で該当箇所だけ差し替える。** 画像・表・書式が保持される。作り直す前に必ず Doc の現在の本文を読み、堀本さんの手修正を取り込む（出典表記の削除、用語の統一など、Doc 側だけに入っていることがある）。

### 9. 報告の形式

1. Doc の URL と Git のパス
2. 調べて分かったこと（戦績は表で。出典も）
3. 記事の軸として何を選び、なぜそうしたか
4. 埋める箇所（`●●`）
5. 確認してほしい点（呼称、人名、食い違っている数字）
