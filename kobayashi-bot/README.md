# 小林bot（代表・小林さんの事前レビューbot）

小林さんに確認を出す **前に**、まず小林botに成果物を投げて「言われそうなこと」を先につぶすためのbotです。
小林さん・社員お互いのコミュニケーション工数を減らすことが目的です。

- 中身は、Googleカレンダー上で小林さんが参加していた会議のうち、**文字起こし／Geminiメモが残っている約90件**（2025年12月〜2026年11月）を読み込み、
  口調・判断基準・よく出る指摘・事業ルールを抽出したものです。
- **あくまで分身です。** 金額・値引き・人事・顧客への回答などの最終判断は必ず小林さん本人に。

## できること（3モード）

| モード | 使い方 | 返ってくるもの |
|---|---|---|
| 事前レビュー | 企画書・提案資料・プレゼン・HP案・管理シート・メール/LINE文面・商談準備メモを貼る or PDF/画像/テキストを添付 | 「これ言われる」指摘（セリフ・理由・直し方）、良い点、出す前チェックリスト |
| 相談・壁打ち | 「これどう進めたらいい？」 | 小林さんならどう考えるかを会話で。逆質問→次の一手 |
| 最終チェック | 修正後の最終版を貼る | 「出してOK / あと一歩 / まだ出さない方がいい」判定 |

コツ：**「何のための資料か」「誰に出すか（決裁者は誰か）」「いつまでか」** を一言添えると精度が上がります。

## ファイル構成

```
kobayashi-bot/
├── prompts/system.md          … 人格・守ること・レビュー手順（ここを直すと挙動が変わる）
├── knowledge/                 … 文字起こしから抽出した知識（system プロンプトに自動で連結）
│   ├── 01_voice.md            … 口調・口癖・褒め方
│   ├── 02_judgement_and_pushbacks.md … 判断基準・指摘パターン・意思決定の仕方
│   ├── 03_business_rules.md   … イベント・スポンサー・RPO・営業管理の数値とルール
│   └── 04_company_context.md  … 会社・サービス・顧客・メンバー・用語集
├── server.js / lib/prompt.js  … API サーバー（Claude API、ストリーミング）
├── public/index.html          … チャット画面
└── scripts/export.js          … プロンプト一式を1ファイルに書き出す
```

## 使い方 A：サーバーなしで今すぐ使う（Claude のプロジェクト機能）

1. `prompts/system.md` と `knowledge/*.md` を Claude（claude.ai）の「プロジェクト」にナレッジとしてアップロード
   （または `npm run export` で `dist/kobayashi-bot-instructions.md` を作り、プロジェクトのカスタム指示に貼る）
2. プロジェクトを社内メンバーに共有
3. 会話の最初に「事前レビューして」「壁打ちしたい」「最終チェックして」と書いて使う

## 使い方 B：社内Webアプリとして立てる

```bash
cd kobayashi-bot
npm install
ANTHROPIC_API_KEY=sk-ant-... BOT_PASSWORD=社内用パスワード npm start   # http://localhost:3100
```

| 環境変数 | 説明 | 既定値 |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude API キー（必須） | – |
| `BOT_PASSWORD` | 設定すると画面でパスワードを要求（社外の人に使わせないため。公開時は必ず設定） | なし |
| `PORT` | ポート | 3100 |
| `KOBAYASHI_BOT_MODEL` | モデル | `claude-opus-5-5` |
| `KOBAYASHI_BOT_EFFORT` | 思考の深さ `low`〜`max` | `high` |

- system プロンプト（約13万字）は1時間のプロンプトキャッシュに載せているので、2回目以降の問い合わせは安く速くなります。
- 安全側の判定で回答が止まった場合に備えて、サーバー側フォールバック（`fallbacks: "default"`）を有効にしています。
- 会話履歴はサーバーに保存しません（ブラウザを閉じると消えます）。

デプロイは親ディレクトリの給与システムと同じく Render / Railway などで `kobayashi-bot` をルートにして `npm start` で動きます。

## 知識の更新（会議が増えたら）

新しい会議の文字起こしが溜まったら、Claude Code でこのリポジトリを開き
「カレンダーで小林さんが参加している◯月以降の会議の文字起こしを読んで、kobayashi-bot/knowledge を更新して」
と頼めば、同じ手順で追記できます。小林さん本人に `knowledge/` を一度見てもらい、
「これは違う」「これは古い」を直してもらうと精度が一気に上がります。

## 注意

- `knowledge/` には顧客名・料金などの社内情報が含まれます。リポジトリは非公開のまま運用してください。
- 文字起こしは自動変換のため、固有名詞・数字に誤りがある可能性があります（資料内で【推測】【要確認】と表記）。
