## 2. 切り替え前にやること

### 2-1. 外部タグ・計測設定の確認

サポートから「外部タグや計測設定の影響が出る可能性」の注意があった。**公開サイトの生HTMLを調べた範囲では、GTM・GA4・Meta Pixel・HubSpot などの外部タグは検出されなかった**（TOP・記事・ニュースの3ページで確認）。ただし旧基盤ではクライアント側で注入される可能性があるため、生HTMLに出ないことは「設定されていない」ことの証明にはならない。

Studio のダッシュボードで以下を確認する。

- 設定 → カスタムコード（head / body）に何か入っていないか
- 外部サービス連携（Google Analytics、Search Console など）の設定有無
- フォームの送信先設定（問い合わせ・資料ダウンロード）

入っていた場合は、**切り替え前にスクリーンショットを撮っておく**。切り替え後に同じ設定が生きているか照合するため。

### 2-3. 判断

サポートは「重要な本番サイトの場合はテスト用プロジェクトで事前検証」を推奨している。外部タグが検出されず、フォーム以外に動的な仕掛けが見当たらないため、テスト検証を省いて直接切り替える選択も取り得る。ただし**フォームの送信だけは切り替え後に必ず実機で確認する**こと。問い合わせが止まると被害が大きい。

## 3. 切り替え手順（サポート回答より）

1. Studio にログイン
2. 対象プロジェクトを開く
3. ダッシュボード → 設定（右パネル） → 一般
4. 公開サイト基盤 → 設定 をクリック
5. 新基盤を選択して保存
6. **サイト更新** を実行
7. 反映まで約5分待つ

## 4. 切り替え後の検証

### 4-1. SSR の判定（Claude Code で実行）

```
bash tools/aeo/check-ssr.sh https://voco.co.jp/case/consulting/oyakudachi_01 接触単価
```

**合格の目安**：本文字数が1000以上、h2が3本以上、「接触単価」が「あり」。
全UA（GPTBot・ClaudeBot・PerplexityBot・Googlebot・Chrome）で同じ結果になることも確認する。

TOP・ニュース記事でも同様に確認する。

### 4-2. メタ情報の確認

ページごとに `<title>` `<meta name="description">` `<link rel="canonical">` `og:image` が出力されるようになったか。全ページ共通の「株式会社VOCO」のままであれば、CMSフィールドとのバインド設定が別途必要。サポートへ項目1として確認済み。

### 4-3. 人の目で確認すること

- **フォームの送信**（問い合わせ・資料ダウンロード）が通るか。実際に送信してみる
- 全ページの表示崩れ（PC幅・スマホ幅）
- 公開中の記事21本・ニュース3本のURLが変わっていないか（サイトマップの件数で確認できる）

## 5. 切り替え後に進むこと

1. **構造化データ（JSON-LD）の設定。** サポートより、CMSの動的ページでは構造化データの値をCMSプロパティに差し込めるとの回答。`name` → 記事タイトル、`articleBody` → 記事本文、`image` → カバー画像、`articleSection` → 見出し。各記事の正本（`content/articles/out/No.xxx_article.html`）の先頭コメントに FAQPage JSON-LD を用意済みなので、これを流用できるか検討する。
2. 下書きのまま残っている18本の公開。
3. 記事の置き場所（`/case/consulting/` の下にある件）の見直し。URLが変わるためリダイレクトとセットで判断する。
