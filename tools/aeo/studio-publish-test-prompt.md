# Studio 公開テスト｜Claude in Chrome 用プロンプト

用途：お役立ち記事を1本だけ**実際に公開**し、生HTMLに本文が出るか（SSR されるか）を検証する。
通常の入稿（下書き保存まで）は `studio-paste-prompt.md`。こちらは公開まで行う検証用で、1回だけ使う。
背景：2026-11-06 時点で voco.co.jp にお役立ち記事は0本。`/column/...` は404フォールバックで、サイトマップにもお役立ち記事のCMSモデルが無い。ニュース記事は公開されているが、生HTMLに本文・見出し・JSON-LD が一切出ていない。

あなたは Web サイトの入稿担当です。いま開いている Studio（プロジェクト voco.co.jp）で、お役立ち記事を**1本だけ実際に公開**してください。目的は記事を増やすことではなく、**公開したページの生HTMLに本文が出るかを確かめること**です。だから下書き保存では終わらせず、公開まで進めてください。

## 0. 守ること

- **本文の文章・見出し・順番を変えない。** 誤字に気づいても直さず、最後に報告する。
- **今回公開するのは1本だけ。** 他の記事・他のページ・テンプレートの見た目は触らない。
- 判断に迷う操作や、ページを新規に作る必要が出た場合は、**手を止めて報告**する。勝手に作らない。
- うまくいかない操作の回避策を試すのは2回まで。できなければ、その状態のまま報告する。
- **報告には必ず「公開されたページのURL」を入れる。** これが無いと検証できません。

## 1. 先に現状を調べて報告する（ここが一番重要）

お役立ち記事は現在 `/download` のページに入っているようです。`/download` は本来「資料ダウンロード」のページで（本文末尾のCTAボタン「資料3点セットをダウンロードする」の遷移先）、記事の置き場所としては想定外です。まずこの構造を確認してください。

公開作業に入る前に、次を調べて書き出してください。**調べた結果、3 の詳細ページが無ければ作業を止めて報告してください。**

1. CMS にどんなモデル（コレクション）があるか。名前を全部挙げる。
2. その中に「お役立ち記事」に当たるモデルがあるか。あれば、登録済みアイテムが何件あり、それぞれ公開状態（公開／下書き／非公開）がどうなっているか。
3. **そのモデルに紐づく詳細ページ（動的ページ／CMSページ）がサイト側に存在するか。** 存在するなら、そのページのパス（URLの形）は何か。例：`/column/[slug]` `/download/[slug]` など。
4. `/download` のページを開き、お役立ち記事がどういう形で置かれているか。CMSリスト（繰り返し要素）として置かれているのか、手で並べた静的な要素なのか。リストなら、各項目のリンク先がどこに向いているか（詳細ページなのか、リンク無しなのか）。
5. `/download` は資料ダウンロードのページとお役立ち記事の一覧が同居している状態か。同居しているなら、それぞれどの部分か。
6. 詳細ページ・一覧ページが「公開済み」か「未公開」か。

※ 3 の詳細ページが無い場合、記事アイテムをいくら公開してもURL が生まれず、検索エンジンにもAIにも1記事として認識されません。その場合は**ページを作らずに、無いことを報告して終了**してください。ページ設計は別途判断します。

## 2. 公開する記事を選ぶ

次の優先順で、1本選んでください。

1. 「お役立ち記事」モデルに**すでに入稿済みのアイテムがある**場合は、その中から「採用イベントの費用対効果はどう測ればいい？」で始まるものを選ぶ。本文に「接触単価」という語が含まれているはずです。
2. 入稿済みアイテムが1件も無い場合は、作業を止めて報告してください。こちらから Google ドキュメントのURLを渡し、`studio-paste-prompt.md` の手順で入稿してから改めて公開します。

選んだアイテムのタイトルとスラッグを報告に書いてください。

## 3. 公開する

1. 選んだアイテムの公開状態を「公開」にする。公開日が未入力なら今日の日付を入れる。
2. **サイト全体の公開（Publish）も実行する。** Studio はアイテムを公開状態にしただけでは実サイトに反映されないことがあります。詳細ページ・一覧ページが未公開なら、それらも公開対象に含めてください。
3. 公開が完了したら、**実際のURL（voco.co.jp で始まるもの）をブラウザで開いて、記事本文が表示されることを確認**する。
4. 表示されない、404になる、URLが分からない、のいずれかであれば、そこで止めて状況を報告する。

## 4. 報告

次を必ず含めてください。

1. **公開されたページのURL**（voco.co.jp で始まる完全なURL）
2. 1 で調べた現状（CMSモデル名の一覧／お役立ち記事モデルの有無とアイテム件数／詳細ページのパス／一覧ページのパス／それぞれの公開状態）
3. 公開したアイテムのタイトルとスラッグ
4. サイト全体の公開（Publish）を実行したかどうか
5. できなかったこと、詰まった点
6. 本文で気になった点（誤字・数字のゆれ）。直していないことを明記する
7. 公開後のページのスクリーンショット（PC幅1枚）

## 補足（堀本さん向け・貼らない）

- 報告でURLをもらったら、Claude Code 側で次を実行して SSR を判定する。

```
bash tools/aeo/check-ssr.sh <公開されたURL> 接触単価
```

  本文字数が 1000 以上・h2 が 3 本以上・「接触単価」が「あり」なら SSR されている。全UAで 0 付近なら JS 描画のみで、GPTBot・ClaudeBot・PerplexityBot からは読まれない。
- 「接触単価」を検索語に使うのは、記事 No.004（費用対効果）の本文にだけ出てくる造語で、テンプレートの共通文言と混ざらないため。別の記事で試す場合は、その記事にしか出てこない語に差し替える。
- 1 の診断だけでも価値がある。詳細ページが無いことが分かれば、「記事を書く前にページを作る」という順番が確定する。
- SSR されていなかった場合の次の手は、HANDOFF 2 節 2 の方針（アイテムを再パブリッシュ → 変わらなければ STUDIO サポートへ照会）。照会時は「同じ STUDIO 製の help.studio.design は生HTMLに本文が出ているのに、当プロジェクトは `__NUXT__` ペイロードにしか本文が無い」と添えると話が早い。
