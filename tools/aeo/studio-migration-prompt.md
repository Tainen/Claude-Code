注意：**本番サイトへの変更**。切り替え前の状態記録を必ず先に行う。
作成：2026-11-06。

いま開いている Studio（プロジェクト voco.co.jp）で、**公開サイト基盤を旧基盤から新基盤へ切り替え**てください。本番サイトへの変更なので、手順を飛ばさず順番に進めてください。

## 0. 守ること

- **ページの内容・デザイン・CMSのデータは一切編集しない。** 触るのは「公開サイト基盤」の設定と「サイト更新」だけです。
- **フォームの送信はしない。** 実際の問い合わせデータが作られてしまうため、送信テストは人が行います。
- 下の手順と画面が違う、見慣れない警告が出る、選択肢の意味が分からない——このいずれかに当たったら、**その場で止めて、画面のスクリーンショットと警告の文言をそのまま報告**してください。自分で判断して進めないでください。
- 操作の回避策を試すのは2回まで。できなければその状態のまま報告してください。

## 1. 切り替え前の状態を記録する（必ず最初に）

切り替えによって外部タグや計測設定に影響が出る可能性があるとサポートから案内されています。**あとで復旧できるように、先に記録してください。**

1. ダッシュボード → 設定 を開き、**カスタムコード**（head / body、名称が違う場合は相当する項目）に何か記述があるか確認する。**あればスクリーンショットを撮り、中身をテキストでも書き出す。**
2. 外部サービス連携（Google Analytics、Search Console、その他）の設定があるか確認し、あればスクリーンショットを撮る。
3. フォームの送信先設定（問い合わせ・資料ダウンロード）を確認し、スクリーンショットを撮る。
4. 現在の「公開サイト基盤」の設定画面を開き、**切り替え前の表示内容をスクリーンショットで記録**する。いま何が選択されているか、選択肢として何があるかを文字でも書き出す。
5. プロジェクトの**作成日**が分かる場所があれば控える（サポートから「2026年6月11日以前の作成か」を聞かれているため）。

ここまでを報告できる状態にしてから、2 に進んでください。

## 2. 切り替える

サポートから案内された手順です。

1. ダッシュボード → 設定（右パネル） → 一般
2. 「公開サイト基盤」の項目 → 「設定」をクリック
3. **新基盤**を選択して保存
4. 確認ダイアログが出たら、**文言をそのまま控えてから**進む。ただし「URLが変わる」「データが削除される」「元に戻せない」といった内容が含まれていた場合は、**進まずに止めて報告**してください。
5. 保存後、**「サイト更新」を実行**する
6. 反映に5分程度かかるため、5分以上待つ

## 3. 切り替え後の確認

1. 次の3つのURLをブラウザで開き、**表示が崩れていないか**を確認する。
   - https://voco.co.jp/
   - https://voco.co.jp/case/consulting/oyakudachi_01
   - https://voco.co.jp/news/news20260929
2. それぞれPC幅でスクリーンショットを撮る。
3. 記事一覧ページ https://voco.co.jp/download を開き、記事の一覧が以前と同じように表示されているか確認する。
4. 問い合わせフォームのページを開き、**フォームが表示され送信ボタンがあること**だけ確認する（送信はしない）。
5. 1 で記録した**カスタムコード・外部サービス連携・フォーム送信先の設定が、切り替え前と同じ内容のまま残っているか**を照合する。消えていたら報告する。

## 4. 報告

次を必ず含めてください。

1. **切り替えが完了したかどうか**（完了／途中で中断／できなかった）
2. 「公開サイト基盤」の設定が、切り替え前は何で、切り替え後は何になったか
3. 確認ダイアログが出た場合、その**文言そのまま**
4. 「サイト更新」を実行したか、実行した時刻
5. 1 で記録した内容（カスタムコードの有無と中身／外部サービス連携／フォーム送信先／プロジェクト作成日）
6. 切り替え前後の設定が同じまま残っていたか。変わっていた項目があればその内容
7. 3 で撮ったスクリーンショット（TOP・記事・ニュースの3枚）と、表示崩れの有無
8. できなかったこと、詰まった点

## 補足（堀本さん向け・貼らない）

- 報告が来たら Claude Code 側で判定する。

```
bash tools/aeo/check-ssr.sh https://voco.co.jp/case/consulting/oyakudachi_01 接触単価
bash tools/aeo/check-ssr.sh https://voco.co.jp/news/news20260929 北海学園
bash tools/aeo/check-ssr.sh https://voco.co.jp/ VOCO
```

  本文字数1000以上・h2が3本以上なら解決。切り替え前の数値は `studio-migration-checklist.md` 2-2 に記録済み。
- **フォームの実送信だけは堀本さんが行う。** Chrome には禁止している（実データが作られるため）。切り替え後いちばん被害が大きいのがフォーム停止なので、ここだけは必ず人の目で確認する。
- 中断して報告が来た場合、止まった理由によってはサポートへ再確認する。ダイアログの文言をそのまま控えさせているのは、そのときの材料にするため。
