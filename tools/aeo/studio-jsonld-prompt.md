# 構造化データ（JSON-LD）の設定｜Claude in Chrome 用プロンプト

用途：記事ページ・ニュースページ・TOPページに構造化データ（JSON-LD）を設定する。
前提：新基盤へ切り替え済み、title とメタ情報は設定済み（HANDOFF 6・7 節）。公開中の全36ページで JSON-LD は0件。
根拠：STUDIO サポート回答（2026-11-06）「CMSの動的ページでは、構造化データ内の値をCMSのプロパティ（タイトル・本文・画像など）に差し込む形で設定できます」。
注意：**本番サイトの設定変更**。ページの内容やデザインは触らない。
作成：2026-11-07。

## 設計方針

- **お役立ち記事（`/case/consulting/:slug`）** → `Article`
- **ニュース（`/news/:slug`）** → `Article`（`NewsArticle` は報道機関向けの性格が強いため、企業のお知らせには `Article` を使う）
- **TOP（`/`）** → `Organization`
- 値は可能な限り **CMSのプロパティにバインド**する。固定文字列で埋めると、記事を追加するたびに手作業が発生するため。
- FAQPage は各記事で内容が異なり、CMSに該当フィールドが無いため**今回は対象外**。

## 0. 守ること

- **ページの内容・デザイン・CMSの記事本文・既に設定済みのメタ情報（ページタイトル等）は一切編集しない。** 触るのは構造化データの設定だけです。
- **フォームの送信はしない。**
- **CMSのフィールドを新規追加しない。** 必要なフィールドが無ければ、無いことを報告して止まってください。
- 画面が説明と違う、設定項目が見つからない、プランの制限で使えない——このいずれかに当たったら、**その場で止めて、スクリーンショットと画面の文言をそのまま報告**してください。自分で判断して進めないでください。
- 操作の回避策を試すのは2回まで。

## 1. 先に構成を調べて報告できる状態にする

設定に入る前に、次を調べて書き出してください。

1. **構造化データの設定項目がどこにあるか。** ページ設定の中か、サイト設定の中か。画面上での名称（「構造化データ」「JSON-LD」「Schema」など）も書く。
2. **設定の方式。** 用意されたスキーマ（Article、Organization など）から選ぶ形式か、JSONを自由に記述する形式か。選択式なら、選べるスキーマの一覧を挙げる。
3. **CMSプロパティを差し込める項目**はどれか。差し込める場合、`/case/consulting/:slug` で選べるプロパティの一覧を挙げる（タイトル・スラッグ・本文・カバー画像・公開日時・最終更新・投稿者 のうちどれが選べるか）。
4. **契約プランによる制限があるか。** 「アップグレードが必要」などの表示が出ていないか。
5. **CMSアイテムごとに個別のJSONを入れられるフィールド**（長文テキストなど）が「記事」モデルにあるか。※ 将来 FAQPage を入れるための確認です。今回は追加しません。

**1 の設定項目が見つからない場合、または 4 でプラン制限がある場合は、ここで止めて報告してください。**

## 2. お役立ち記事（`/case/consulting/:slug`）に Article を設定

`@type` は `Article` を選びます。各項目に、対応するCMSプロパティをバインドしてください。

| 項目 | 設定する値 |
|---|---|
| headline | CMSの「タイトル」をバインド |
| image | CMSの「カバー画像」をバインド |
| datePublished | CMSの「公開日時」をバインド |
| dateModified | CMSの「最終更新」をバインド |
| author | CMSの「投稿者」をバインド。名前が取り出せない場合は、固定で `株式会社VOCO` と入れる |
| publisher | 固定で `株式会社VOCO`。ロゴの指定欄があればサイトのロゴ画像を指定する |
| articleBody | CMSの「本文」をバインド |
| mainEntityOfPage | そのページのURL。自動で入る場合はそのまま |

- **バインドできない項目は、固定文字列で埋めずに空のままにして報告してください。** 固定で埋めると全記事で同じ値になり、かえって不正確になります（publisher だけは例外で、固定で構いません）。
- `articleSection` という項目があれば、CMSの見出しや本文から取れるものを設定してください。無ければ飛ばして構いません。

## 3. ニュース（`/news/:slug`）に Article を設定

2 と同じ要領で設定してください。`@type` は `Article` です（`NewsArticle` ではありません）。ニュースモデルのフィールド名が記事モデルと違う場合は、相当するものに読み替えてください。

## 4. TOPページ（`/`）に Organization を設定

`@type` は `Organization`。値は**サイト内の会社概要ページ（`/company`）に書かれている内容をそのまま使ってください。** 新しい情報を作らないでください。

| 項目 | 設定する値 |
|---|---|
| name | 株式会社VOCO |
| url | https://voco.co.jp/ |
| logo | サイトのロゴ画像 |
| address | `/company` に記載の本社所在地 |
| telephone | `/company` に記載があれば。無ければ空 |
| sameAs | サイトのフッターやヘッダーに公式SNSのリンクがあれば、そのURL。無ければ空 |

`/company` に記載が無い項目は**空のままにして、報告に「記載なし」と書いてください。**

## 5. 公開する

1. 設定を保存する。
2. **「サイト更新」を実行**する。実行前に「更新差分を確認する」を開き、**構造化データ以外の変更が含まれていないか**を確認する。ページ内容の変更が混ざっていたら、**実行せずに報告**してください。
3. 反映に5分程度かかるため、5分以上待つ。

## 6. 確認

次の3つのURLをブラウザで開き、ページのソースに `application/ld+json` を含む `<script>` が入っているかを確認してください。入っていれば、その**中身をそのままコピーして報告**してください。

- https://voco.co.jp/case/consulting/oyakudachi_01
- https://voco.co.jp/news/news20260929
- https://voco.co.jp/

## 7. 報告

1. **設定が完了したかどうか**（完了／途中で中断／できなかった）
2. 1 で調べた構成（設定項目の場所と名称／方式／選べるスキーマ／差し込めるCMSプロパティ一覧／プラン制限の有無／記事モデルに長文テキストのフィールドがあるか）
3. **バインドできた項目と、空のままにした項目**。空にした理由も
4. `/company` から取った Organization の値と、記載が無かった項目
5. 「サイト更新」の実行可否と差分確認の結果

## 補足（堀本さん向け・貼らない）

- 報告が来たら Claude Code 側で公開中の全36ページを実測し、JSON-LD の有無と中身の妥当性（必須プロパティの欠落、値の重複）を確認する。
- **`Article` を選んだ理由**：`NewsArticle` は報道機関向けの性格が強く、企業のお知らせに使うと Google のリッチリザルト要件（発行元の情報など）で不利になりうる。`BlogPosting` でも実害は無いが、`Article` が最も無難。
- **バインドできない項目を固定文字列で埋めない**ようにしているのは、全21記事で `datePublished` が同じ日付になるような事故を防ぐため。空のほうが、誤った値より安全。
- **FAQPage は今回対象外。** 各記事の正本の先頭コメントに FAQPage の JSON-LD を用意済みだが、記事ごとに内容が異なるため、CMSに長文テキストのフィールドを追加して記事ごとにJSONを入れる必要がある。項目5でその可否だけ確認させている。descriptionフィールドの追加と同じタイミングで判断するとよい。
- 設定後の検証は、Google のリッチリザルトテストでも確認できる（https://search.google.com/test/rich-results）。構文エラーや必須プロパティの欠落が出ないかを見る。
