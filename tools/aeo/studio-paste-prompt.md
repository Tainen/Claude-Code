# Studio 記事入稿｜Claude in Chrome 用プロンプト（1記事ごと）

用途：Google ドキュメントの記事を Studio の CMS「お役立ち記事」に入稿する作業を Claude in Chrome に任せる。
人がやるのは「Doc の URL を渡す」「最後にプレビューを見て公開ボタンを押す」の2つだけ。
前提：記事の見た目（H2 の帯、太字のマーカー、表の色など）は Studio のテンプレート側で設定済み（`studio-style-prompt.md`）。本文を貼るだけで同じ見た目になる。

Google ドキュメント：【ここに Doc の URL を貼る】

あなたは Web サイトの入稿担当として、上の Google ドキュメントの記事を、いま開いている Studio の CMS「お役立ち記事」に新しいアイテムとして入稿してください。文章は一切変えません。公開はしません。

## 0. 守ること

- **公開しない。** 「下書き」または「非公開」で保存して終わる。公開は私が行う。
- Doc の文章・見出し・順番を変えない。誤字に気づいても直さず、最後に報告する。
- 既存の記事や他のページは触らない。
- Doc の区切り線（横線）より下は「掲載用メタ情報」。**本文には貼らない。** タイトル・スラッグ・カテゴリ・ディスクリプションはここから読み取る。
- 途中でうまくいかない操作があれば、回避策を試すのは2回まで。それでもできなければ、そのまま保存して「できなかったこと」として報告する。

## 1. Doc を読む

新しいタブで Doc を開き、次を控える。

- 区切り線より下の「タイトル」「記事番号／スラッグ」「カテゴリ」「メタディスクリプション」「H2 に指定する行」
- 本文中の太字の箇所（貼り付け後に残っているか確認するため）
- 画像の枚数と、それぞれの直後にある「【画像N：…】」のキャプション行

## 2. CMS アイテムを作る

1. CMS →「お役立ち記事」→ アイテムを追加。
2. タイトル欄に、Doc の「タイトル」をそのまま入れる（「｜」以降も含めて全文）。本文の先頭にはタイトルを貼らない。
3. スラッグに Doc の「スラッグ」（例：article-004）を入れる。
4. カテゴリを Doc の「カテゴリ」に合わせて選ぶ。該当がなければ最も近いものを選び、報告に書く。
5. 公開日は今日。公開状態は「下書き」または「非公開」。
6. ディスクリプション（説明文・SEO 説明などの欄があれば）に「メタディスクリプション」を入れる。

## 3. 本文を貼る

1. Doc の本文（先頭から区切り線の直前まで）をコピーして、本文のリッチテキスト欄に貼る。
2. 見出しレベルを確認する。Doc の「H2 に指定する行」に挙がっている行がすべて H2 になっているか。「よくある質問」の下の質問文は H3。落ちていたら直す。見出し（H2・H3）の文字に太字が付いていたら解除する（見出し内の太字は Studio で下線扱いになる）。
3. 太字が残っているか確認する。消えていたら Doc を見て同じ箇所を太字にする。
4. 「まとめ」の箇条書きがリストになっているか確認する。番号や「・」が文字として貼られていたら、リストブロックに直す。
5. 表があれば、列と行が崩れていないか確認する。崩れていたら Studio の表を作り直して、セルの文言を Doc から移す。
6. 「【画像N：…】」のキャプション行を見つけ、次の手順で画像に置き換える。
   - Doc の該当画像を右クリック → 画像を保存（ファイル名は Doc のキャプション末尾にある `No.xxx_imgN.png`）。
   - Studio でそのキャプション行の位置に画像を挿入し、保存した画像をアップロードする。
   - 代替テキスト（alt）欄があれば、キャプションの「一場面」までの文章を入れる。
   - キャプション行の文字は削除する。
7. 本文末尾の「採用のことを、一度話してみませんか。…」の段落の下に、ボタンコンポーネントを2つ置く。ラベルは「今すぐ無料でプロに相談する」「資料3点セットをダウンロードする」。既存記事に同じボタンがあれば、それを複製してリンク先も同じにする。
8. 「この記事を書いた人：…」の段落は、著者ボックスのコンポーネントが用意されていればそれに置き換える。無ければ段落のまま残す。

## 4. サムネイル

- メイン画像（サムネイル／OGP）は私が別に用意する。空欄のままにしてよい。必須で空欄のまま保存できない場合だけ、本文1枚目の画像を仮に入れ、報告に「サムネイルは仮」と書く。

## 5. 確認して保存

1. 下書きとして保存する。
2. プレビューを PC 幅とスマホ幅で開き、次を確認する。見出しが H2/H3 になっているか／太字にマーカーが付いているか／画像が3枚とも表示されているか／表が横に切れていないか／ボタンが2つあるか。
3. スクリーンショットを PC・スマホ各1枚撮る。

## 6. 報告

次の形式で報告する。

- アイテム名とスラッグ、公開状態（下書き）
- 貼り付け後に手で直した箇所（見出しレベル、太字、リスト、表）
- 画像3枚の挿入結果と、alt に入れた文
- できなかったこと（あれば）と、その状態でどう保存したか
- Doc の文章で気になった点（誤字、数字のゆれなど）。直していないことを明記する
- 私が公開前に見るべき箇所（スクリーンショットの該当位置）

## 補足（堀本さん向け・貼らない）

- 1行目の Doc URL を差し替えるだけで、どの記事にも使える。
- Doc は `node tools/article/make-doc-html.mjs No.xxx --out <path>` で作る。末尾に「掲載用メタ情報」が付き、この プロンプトはそこを読む。
- Doc を手で修正した場合は、その修正が正本（Git の `content/articles/out/No.xxx_article.html`）に戻っていないことがある。次に Claude Code で Doc を作り直すときは、Doc の現在の本文を先に読み込ませる（HANDOFF 4-2 の運用）。
- 公開後の TOP「お役立ち記事」枠の差し替え（最新3本）は別作業。まとめて週1で行う。
